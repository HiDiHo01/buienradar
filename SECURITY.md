# Security Policy

## Supported versions

Security fixes are considered for the currently maintained version of the project. The repository's release history and package metadata should be used to determine whether a particular release is maintained; do not assume an undocumented support window.

## Reporting a vulnerability

Please do not disclose exploitable vulnerabilities in public issues or pull requests.

Use GitHub's **Report a vulnerability** feature on this repository's **Security** tab to submit a private vulnerability report when that feature is available. If private reporting is unavailable, contact the repository maintainer privately through a verified contact method listed on the maintainer's GitHub profile and request a secure channel. Do not include exploit details in a public issue while arranging contact.

Include, where possible:
- A description of the vulnerability and its potential impact.
- Affected versions, files, or commit references.
- Minimal reproduction steps or a proof of concept that does not expose real secrets or third-party data.
- Any known mitigations.

## Response and disclosure

The maintainer will assess the report, determine affected versions, and coordinate a fix and disclosure with the reporter. No specific response or remediation time is guaranteed by this policy.

Please give maintainers a reasonable opportunity to investigate and release a fix before public disclosure. Do not access, modify, or retain data that is not yours while investigating a suspected vulnerability.

## Scope

Security reports may include unsafe handling of API responses, request or URL construction issues, dependency vulnerabilities, unintended disclosure through logs, and other vulnerabilities that affect this library or its users.
